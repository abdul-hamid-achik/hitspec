title: "Exit Codes"
description: "Reference for all hitspec CLI exit codes for use in scripts and CI/CD pipelines."

hitspec uses specific exit codes to indicate the result of a test run. These are useful for scripting and CI/CD integration.

## Exit Codes

| Code | Constant | Description |
|------|----------|-------------|
| `0` | `ExitSuccess` | All tests passed |
| `1` | `ExitTestFailure` | One or more tests failed or thresholds exceeded |
| `2` | `ExitParseError` | A file could not be loaded: invalid syntax, a duplicate `@name`, or a circular `@depends` in a `.http` / `.hitspec` file |
| `3` | `ExitConfigError` | Configuration error: a `hitspec.yaml` (or `--config` file) that is missing or cannot be parsed, an `--env-file` that does not exist, a missing or invalid `--cacert`, `--cert`, `--key` or `--proxy`, or a `--metrics-port` that is already in use. These stop the command before any request is sent. `validate`, `studio`, `serve` and `contract` also exit `3` on a broken `hitspec.yaml` |
| `4` | `ExitNetworkError` | At least one request got no response because the connection failed: connection refused or unreachable, DNS resolution failure, TLS handshake or certificate error, the request timeout expiring before a connection was established, or the connection reset or closed before a response arrived. This includes an unreachable OAuth2 token endpoint and an unreachable `@waitFor` target |
| `64` | `ExitUsageError` | Usage error: an unknown flag or command, a flag value the parser rejects (for example `--concurrency abc`), a missing required flag, the wrong number of arguments, `-` combined with other files, `--watch` or `--stress`, `--dry-run` combined with `--stress`, invalid `hitspec mcp` arguments, or `--name` / `--tags` that matched no request in any file. hitspec prints `Run 'hitspec <cmd> --help' for usage.` for these. Errors a command finds while doing its work keep their own code: a missing file or an unknown export format exits `1` |
| `130` | `ExitInterrupted` | The run was stopped with Ctrl+C (SIGINT) or SIGTERM. The results of the requests that finished are printed, `--output-file` is written, and requests that had not started are marked as cancelled. A second Ctrl+C exits immediately |

## Precedence

`hitspec run` always runs every file it can, even when another file fails to load. When several outcomes apply, the exit code follows this order: `2` (a file could not be loaded) over `4` (a request hit a network error) over `1` (a request failed) over `64` (filters matched nothing) over `0`. A run with a broken file never exits `0`, so a broken file cannot hide behind green results. An interrupted run exits `130` whatever else happened.

### Network errors and timeouts

Exit `4` means hitspec could not reach the server, so there is nothing to assert on: use it to tell "the API is down or unreachable" apart from "the API answered wrongly" (`1`). It applies only to connection-level errors. A request that connects but then exceeds `@timeout` or `--timeout` while waiting for the response is an ordinary test failure (`1`), and so is a response whose body breaks off part-way, because a response did arrive. Requests skipped because a dependency failed do not change the exit code on their own.

## Usage in Scripts

```bash
hitspec run tests/ --env staging
EXIT_CODE=$?

case $EXIT_CODE in
  0) echo "All tests passed" ;;
  1) echo "Tests failed" ;;
  2) echo "Parse error in test files" ;;
  3) echo "Configuration error" ;;
  4) echo "Network error: the API could not be reached" ;;
  64) echo "Invalid CLI usage" ;;
  130) echo "Interrupted" ;;
  *) echo "Unknown exit code: $EXIT_CODE" ;;
esac
```

## CI/CD Usage

Most CI systems treat any non-zero exit code as failure. hitspec's exit codes let you distinguish between test failures and infrastructure issues. A step that accepts only `0` and `1` must also handle `4` (the API could not be reached) and `130` (interrupted):

```yaml
# GitHub Actions
- name: Run API tests
  run: hitspec run tests/ --output junit --output-file results.xml
  continue-on-error: true

- name: Check results
  run: |
    if [ ${{ steps.test.outcome }} == 'failure' ]; then
      echo "Tests failed - check results.xml"
    fi
```

<Tip>
Use `--bail` to stop on the first failure and exit immediately with that failure's code (`1` for a failed test, `4` for a network error). Without `--bail`, hitspec runs all tests before exiting.
</Tip>
